座・Navi　試験要領書
Za-Navi 座席予約・行先管理 Webアプリケーション
作成日：2026-06-09
対象バージョン：DB接続版（zaseki1 DB / Tomcat 9 / Java 21）
試験環境：http://localhost:8080/za-navi/
管理者アカウント：userId=1001 / password=pass1001
一般ユーザー例：userId=1002 / password=pass1002

1. 試験目的

座・Naviの全機能（ログイン・行先登録・座席予約・代理予約・検索・マスタ管理）が仕様どおりに動作し、正常系・異常系ともにエラーなく応答することを確認する。また管理者権限によるアクセス制御が正しく機能していることも検証する。

2. 試験環境・前提条件

項目内容
WebサーバーApache Tomcat 9（Eclipse WTP 管理）
アプリURLhttp://localhost:8080/za-navi/ControlServlet?action=login
DBMySQL 8.0　データベース名: zaseki1
初期データ部署6件・座席180席（三田/芝浦/中野 × 1F/2F × A/B/C × 10席）・ユーザー200名
管理者アカウントuserId: 1001　password: pass1001（admin=1）
一般アカウント例userId: 1002〜1200　password: pass＋userId
前提Tomcat が起動しており、/ControlServlet?action=login が HTTP 200 を返すこと

6. 既知事項・注意点

DBUtil.java のパスワード：リポジトリ上は your_password プレースホルダーになっています。実際にローカルで動かす際は eclipse-workspace 側の DBUtil.java を編集し、自環境の MySQL root パスワードを設定してください。
フロアマップ画像ファイル：新しい拠点を追加した場合、画像ファイル（例: office_渋谷_1F.png）を webapp/images/ に追加し、さらに SeatsDAO.OFFICE_IMAGES（SeatsDAO.java 29〜45行目）にキーと画像ファイル名を登録する必要があります。
T08 権限チェック：現在の実装は ControlServlet の管理者アクション判定（isAdmin フラグ）でリダイレクトします。直接URLアクセス時にログイン済み・非管理者の場合は login 画面へリダイレクトされる設計です。
