## 1. システムの概要と目的

**座・Navi（Za-Navi）** は、会社のオフィスで使う「座席予約・行先登録システム」です。

### できること

| 機能 | 誰が使う |
|------|---------|
| 行先登録（出社・在宅・出張） | 一般社員 |
| 座席予約（拠点→フロア→エリア→席） | 一般社員 |
| 予約確認・キャンセル | 一般社員 |
| 氏名検索・部門検索 | 全員 |
| 代理予約（他の社員の席を予約） | 管理者 |
| 座席利用状況の確認 | 管理者 |
| 座席マスタの追加・更新・削除 | 管理者 |

### 技術スタック

| 技術 | 役割 |
|------|------|
| Java 8+ | バックエンド（処理） |
| JSP + JSTL | フロントエンド（画面） |
| CSS | デザイン |
| MySQL | データベース |
| Apache Tomcat | Webサーバー |
| Eclipse | 開発環境（IDE） |

## 2. MVC2アーキテクチャ入門

このシステムは **MVC2（Model-View-Controller）パターン** で作られています。
まずこのパターンを理解することが、すべてのコードを読む上での基礎になります。

### MVCとは何か

```
ブラウザ（画面）
    ↓ リクエスト（例: ?action=reserve）
┌─────────────────────────────────────────┐
│           ControlServlet                │  ← Controller（C）
│    「action の値を見て振り分ける係」      │
└─────────────────────────────────────────┘
    ↓ execute() を呼び出す
┌─────────────────────────────────────────┐
│           XXXLogic（例: ReserveLogic）   │  ← Model（M）
│    「実際の処理・計算・DB操作をする係」   │
└─────────────────────────────────────────┘
    ↓ DAOを呼んでデータを取得し
    ↓ req.setAttribute() で結果をセット
    ↓ JSPのパスを return
┌─────────────────────────────────────────┐
│           XXX.jsp（例: reserve.jsp）     │  ← View（V）
│    「データを受け取って画面を作る係」     │
└─────────────────────────────────────────┘
    ↓ HTML として返す
ブラウザ（画面表示）
```

### なぜこの分け方をするのか

**分けない場合（初心者が最初にやりがちな書き方）：**
```java
// JSPの中にデータベース操作と画面表示が混ざっている → 修正がとても大変
<%
  Connection conn = DriverManager.getConnection(...);
  PreparedStatement ps = conn.prepareStatement("SELECT ...");
  ResultSet rs = ps.executeQuery();
  while (rs.next()) {
    out.println("<tr><td>" + rs.getString("name") + "</td></tr>");
  }
%>
```

**MVC2で分けた場合（このシステムの書き方）：**
- ControlServlet → リクエストを受けて振り分けるだけ
- Logic → データベースを操作して結果を計算するだけ
- JSP → 渡されたデータを表示するだけ

→ **修正したいときに、どこを直せばいいかがすぐわかる**

初期データは6部署（D001〜D006）が登録されています。

#### users（社員アカウント）

| カラム名 | 型 | 説明 |
|---------|-----|------|
| user_id | INT | 社員番号（主キー）例: 1001 |
| password | VARCHAR(20) | パスワード 例: "pass1001" |
| b_id | VARCHAR(10) | 所属部署ID（departmentsの外部キー） |
| name | VARCHAR(30) | 氏名 例: "田中太郎" |
| admin | TINYINT(1) | 権限（0=一般、1=管理者） |

**ポイント**: user_id は `INT` だが、Javaプログラム内では `String`（文字列）として扱っています。
DAOクラスの境界でだけ変換します。なぜかというと、もともとString型で設計されていた歴史的経緯があり、
変更の影響範囲を最小限にするためです。

---

#### seats（座席マスタ）

| カラム名 | 型 | 説明 |
|---------|-----|------|
| seat_id | INT(3) | 座席ID（主キー）例: 1 |
| base_name | VARCHAR(50) | 拠点名 例: "三田" |
| f_name | VARCHAR(10) | フロア名 例: "1F" |
| area_name | VARCHAR(10) | エリア名 例: "A" |
| seat_name | VARCHAR(20) | 席番号 例: "A-01" |

初期データは自動生成SQLで **3拠点 × 2フロア × 3エリア × 10席 = 180席** が登録されます。

```sql
-- この SQL が 180 席を一気に生成している
INSERT INTO seats (seat_id, base_name, area_name, f_name, seat_name)
SELECT
    ROW_NUMBER() OVER (ORDER BY b.base_name, f.f_name, a.area_name, n.num) AS seat_id,
    ...
FROM (SELECT '三田' ... UNION ALL SELECT '芝浦' ...) b
CROSS JOIN (SELECT '1F' ... UNION ALL SELECT '2F') f
CROSS JOIN (SELECT 'A' ... UNION ALL SELECT 'B' UNION ALL SELECT 'C') a
CROSS JOIN (SELECT 1 ... UNION ALL ... UNION ALL SELECT 10) n;
```

`CROSS JOIN` は「総当たり組み合わせ」を作る命令です。
3拠点 × 2フロア × 3エリア × 10席 = 180行が一度に生成されます。

---

#### reservations（予約・行先登録）

| カラム名 | 型 | 説明 |
|---------|-----|------|
| reserve_id | INT | 予約ID（自動採番・主キー） |
| user_id | INT(10) | 誰の予約か |
| register_id | INT(10) | 登録した人（代理予約の場合は管理者ID） |
| reserve_date | DATE | 対象日 |
| place | VARCHAR(30) | 行先（"出社"/"在宅"/"出張"） |
| seat_id | INT(3) | 座席ID（0=座席なし） |
| memo | VARCHAR(200) | メモ（任意） |
| cancel_flag | TINYINT(1) | 取消フラグ（0=有効、1=取消済） |
| seat_active_key | (生成列) | 重複チェック用の仕掛け（後述） |
| user_active_key | (生成列) | 重複チェック用の仕掛け（後述） |

#### 「生成列」による重複防止の仕組み（重要！）

```sql
-- 同じ日・同じ席に2人が予約できないようにする制約
seat_active_key INT GENERATED ALWAYS AS
    (CASE WHEN cancel_flag = 0 AND seat_id > 0 THEN seat_id END) STORED,

-- 同じ人が同じ日に2件以上の有効な予約を持てないようにする制約
user_active_key INT GENERATED ALWAYS AS
    (CASE WHEN cancel_flag = 0 THEN user_id END) STORED,

CONSTRAINT uq_reservations_seat_active UNIQUE (reserve_date, seat_active_key),
CONSTRAINT uq_reservations_user_active UNIQUE (reserve_date, user_active_key)
```

**なぜこんな書き方をするのか？**

単純に `UNIQUE (reserve_date, seat_id)` にすると、
キャンセル済みの予約があったとき、その同じ日・同じ席に新しい予約が入れられなくなってしまいます。

「生成列」の仕掛け：
- `cancel_flag=0`（有効）のとき → `seat_active_key = seat_id`（値あり）
- `cancel_flag=1`（取消済）のとき → `seat_active_key = NULL`（値なし）

MySQLのUNIQUE制約は **NULLどうしを「同じ」と見なさない** ため、
キャンセル済みの行はいくらあっても重複チェックの対象にならない、という仕組みです。

## 5. entityパッケージ（データの入れ物）

`entity` パッケージのクラスは **データベースの1テーブル1行分のデータを入れる入れ物** です。
「JavaBean」や「POJO（Plain Old Java Object）」とも呼ばれます。

特徴：
- フィールド（変数）はすべて `private`
- `getter`（取得用メソッド）と `setter`（セット用メソッド）だけを持つ
- ロジック（処理）は書かない

### Account.java

```java
package entity;

public class Account {
    private String userId;    // ログインID（例: "1001"）
    private String password;  // パスワード
    private String name;      // 氏名
    private String bId;       // 所属部署ID（例: "D001"）
    private int admin;        // 0=一般、1=管理者

    // コンストラクタ（引数なし）
    public Account() {}

    // コンストラクタ（全フィールド指定）
    public Account(String userId, String password, String name, String bId, int admin) {
        this.userId = userId;
        // ...
    }

    // getter/setter
    public String getUserId() { return userId; }
    public void setUserId(String userId) { this.userId = userId; }
    // ...（以下同様）
}
```

**ポイント**：`user_id` はDBでは `INT` ですが、Javaでは `String userId` として持っています。
これは歴史的経緯で、DAOクラスでのみ変換が行われます。

### Seat.java

座席の「場所」を4段階の階層で表します。

```java
public class Seat {
    private int seatId;       // 座席ID（例: 1）
    private String baseName;  // 拠点（例: "三田"）
    private String fName;     // フロア（例: "1F"）
    private String areaName;  // エリア（例: "A"）
    private String seatName;  // 席番号（例: "A-01"）
}
```

「三田 1F Aエリア A-01番」のように、どのオフィスのどの席かが一意に特定できます。

### Reservation.java

予約1件を表します。出社・在宅・出張のどれでも同じクラスを使います。

```java
public class Reservation {
    private int reserveId;      // 予約ID（自動採番）
    private String userId;      // 予約の本人
    private String registerId;  // 登録した人（代理予約なら管理者ID）
    private String reserveDate; // 対象日（例: "2026-06-10"）
    private String gyosaki;     // "出社" / "在宅" / "出張"
    private String memo;        // メモ（任意）
```

このマッピングはDAOクラスが担当します。

## 6. daoパッケージ（データベースとのやりとり）

DAO（Data Access Object）パッケージは、**データベースとのやりとりに特化したクラス群** です。
SQLを書いてDBにアクセスし、結果をentityオブジェクトに詰め替えて返します。

Logicクラスはデータが欲しいときにDAOを呼ぶだけでよく、SQL文を自分で書く必要がありません。

### DBUtil.java（DB接続ユーティリティ）

すべてのDAOはここから `Connection`（DB接続）を取得します。
接続情報を1か所にまとめることで、接続先を変えたいときにここだけ直せばよくなっています。

```java
public class DBUtil {
    private static final String URL =
        "jdbc:mysql://localhost:3306/zaseki1?useSSL=false&serverTimezone=Asia/Tokyo&characterEncoding=UTF-8";
    private static final String USER = "root";
    private static final String PASS = "your_password";

    // static ブロック: クラスが最初に読み込まれたときに1度だけ実行される
    static {
        try {
            Class.forName("com.mysql.cj.jdbc.Driver"); // JDBCドライバの読み込み
        } catch (ClassNotFoundException e) {
            throw new RuntimeException("MySQL JDBCドライバが見つかりません", e);
        }
    }

    // Connection を返す（try-with-resources で自動クローズ可能）
    public static Connection getConnection() throws SQLException {
        return DriverManager.getConnection(URL, USER, PASS);
    }
}
```

**JDBCの基本パターン**（このコードで繰り返し出てくる）：
```java
try (Connection conn = DBUtil.getConnection();           // 1. 接続を取得
     PreparedStatement ps = conn.prepareStatement(sql)) { // 2. SQLをセット
    ps.setString(1, someValue);                           // 3. パラメータをセット
    try (ResultSet rs = ps.executeQuery()) {              // 4. SQL実行
        while (rs.next()) {                               // 5. 結果を1行ずつ取得
            // rs.getString("column_name") で値を取り出す
        }
    }
} catch (SQLException e) {
    throw new RuntimeException("エラーメッセージ", e);
}
// try-with-resources により、ブロックを抜けると conn/ps/rs が自動的にクローズされる
```

なぜ `PreparedStatement` を使うのか？
- `?` プレースホルダーを使うことで **SQLインジェクション攻撃を防げる**
- 例: `WHERE name = '` + name + `'` のように文字列を直接連結すると、
  `name` に `' OR '1'='1` のような文字が入ったとき全データが取れてしまう危険がある

### AccountsDAO.java（ユーザー情報）

主要メソッド一覧：

| メソッド | 何をするか |
|---------|-----------|
| `findById(String userId)` | IDで1人のアカウントを取得 |
| `authenticate(String userId, String password)` | ログイン認証（一致すれば返す、しなければnull） |
| `findAll()` | 全社員一覧 |
| `findByName(String keyword)` | 氏名の部分一致検索 |
| `search(String bId, String userIdKeyword)` | 部署・社員IDで絞り込み検索 |
| `findByBId(String bId)` | 指定部署のメンバー全員 |

`authenticate` メソッドの解説：

```java
public Account authenticate(String userId, String password) {
    String sql = "SELECT user_id, password, b_id, name, admin FROM users WHERE user_id = ? AND password = ?";
    try (Connection conn = DBUtil.getConnection();
         PreparedStatement ps = conn.prepareStatement(sql)) {
        ps.setInt(1, Integer.parseInt(userId));  // ? の1つ目 = user_id
        ps.setString(2, password);               // ? の2つ目 = password
        try (ResultSet rs = ps.executeQuery()) {
            if (rs.next()) return map(rs);  // 1行取れたら認証成功
        }
    }
    return null;  // 0行なら認証失敗
}
```

`map(ResultSet rs)` というプライベートメソッド（DBの行 → Accountオブジェクトへの変換）：

```java
private Account map(ResultSet rs) throws SQLException {
    return new Account(
        String.valueOf(rs.getInt("user_id")), // INT → String 変換
        rs.getString("password"),
        rs.getString("name"),
        rs.getString("b_id"),
        rs.getInt("admin")
    );
}
```

### ReservationsDAO.java（予約情報）

最も複雑なDAOです。主要メソッド：

| メソッド | 何をするか |
|---------|-----------|
| `findByUserId(String userId)` | ある人の有効な予約一覧（過去含む） |
| `findTodayByUserId(String userId)` | ある人の今日の予約 |
| `findByDate(String date)` | ある日の全予約（管理者サマリ用） |
| `findActiveByUserAndDate(String userId, String date)` | ある人のある日の有効な予約（重複チェック用） |
| `getSeatUsageForDate(String date)` | ある日の座席使用状況（Map&lt;seatId, userId&gt;） |
| `add(Reservation r)` | 予約を新規登録 |
| `cancel(int reserveId)` | 予約を取消（cancel_flag=1に更新） |

`getSeatUsageForDate` は埋有率計算に使われる重要なメソッドです：

```java
public Map<Integer, String> getSeatUsageForDate(String date) {
    // 「その日に有効な予約があって、座席IDが0より大きい」行を取得
    String sql = "SELECT seat_id, user_id FROM reservations "
```

通常の `HashMap` は順序を保証しませんが、`LinkedHashMap` は **入れた順序を保持** します。

### LoginLogic.java（ログイン処理）

```java
public class LoginLogic implements Logic {
    @Override
    public String execute(HttpServletRequest req, HttpServletResponse res) throws Exception {
        String action = req.getParameter("action");
        if ("doLogin".equals(action)) {
            return doLogin(req, res);  // フォーム送信された場合
        }
        return "/WEB-INF/jsp/login.jsp";  // 画面表示だけの場合
    }

    private String doLogin(HttpServletRequest req, HttpServletResponse res) throws IOException {
        String userId   = req.getParameter("userId");
        String password = req.getParameter("password");

        // DBで照合
        Account account = new AccountsDAO().authenticate(userId, password);
        if (account == null) {
            req.setAttribute("errorMsg", "ユーザーIDまたはパスワードが正しくありません。");
            return "/WEB-INF/jsp/loginNG.jsp";  // 失敗
        }

        // セッションを発行してユーザー情報を保存
        HttpSession session = req.getSession(true);  // true = セッションがなければ新規作成
        session.setAttribute("userId",   account.getUserId());
        session.setAttribute("userName", account.getName());
        session.setAttribute("isAdmin",  account.getAdmin() == 1);  // boolean に変換
        session.setAttribute("bId",      account.getBId());

        // 権限によってメニュー画面を変える
        if (account.getAdmin() == 1) {
            res.sendRedirect(req.getContextPath() + "/ControlServlet?action=adminMenu");
        } else {
            res.sendRedirect(req.getContextPath() + "/ControlServlet?action=menu");
        }
        return null;  // redirect したので forward は不要
    }
}
```

**セッションとは？**
HTTPは「状態を持たない」プロトコルなので、次のリクエストでは前回の情報を覚えていません。
`HttpSession` を使うことで、**ブラウザとサーバー間の「会話の続き」を記憶** できます。
`session.setAttribute("userId", "1001")` でデータを保存し、
`session.getAttribute("userId")` で取り出します。

**forward と redirect の違い**：
- `forward`（ControlServletが行う）：URL変わらず、req/resをそのまま引き継いでJSPへ渡す
- `redirect`（`sendRedirect`）：ブラウザに「このURLへ行け」と命令。URLが変わる。

ログイン成功後にredirectするのは「戻るボタンを押すとフォームが再送信されてしまう問題」を防ぐためです。
（PRGパターン：Post-Redirect-Get）

## 8. controlパッケージ（司令塔）

### ControlServlet.java

このクラスがすべてのHTTPリクエストを受け取る「玄関口」です。

**重要な3つの役割**：

#### 1. 文字コードの設定
```java
req.setCharacterEncoding("UTF-8");  // リクエストの文字コード
res.setCharacterEncoding("UTF-8");  // レスポンスの文字コード
```
これを忘れると日本語が文字化けします。

#### 2. キャッシュ無効化
```java
res.setHeader("Cache-Control", "no-store, no-cache, must-revalidate");
```
ブラウザが古い画面をキャッシュして「予約したのに反映されない」ように見える問題を防ぎます。

#### 3. セッションチェック（ログイン確認）
```java
if (!action.equals("login") && !action.equals("doLogin")) {
    HttpSession session = req.getSession(false);  // false=セッションがなくてもnullを返す
    if (session == null || session.getAttribute("userId") == null) {
        res.sendRedirect(req.getContextPath() + "/ControlServlet?action=login");
        return;  // ログイン画面へ強制リダイレクト
    }
}
```

ログインしていない状態で `?action=menu` などにアクセスしようとすると、
強制的にログイン画面へ飛ばされます。

#### dispatch メソッド（振り分け）

```java
private String dispatch(String action, ...) throws Exception {
    switch (action) {
        case "login":
        case "doLogin":
            return new LoginLogic().execute(req, res);  // LoginLogicに処理を委譲

        case "reserve":
        case "doReserve":
            return new ReserveLogic().execute(req, res);

        // ...（他のactionも同様）
    }
}
```

`action=login` も `action=doLogin` も同じ `LoginLogic` を呼んでいます。
ログイン画面を **表示する** のか、フォームを **送信する** のかの判断は、LoginLogic の内部で行います。

## 9. JSPビュー（画面の作り方）

### JSPとは

JSP（JavaServer Pages）はHTMLの中にJavaコードを埋め込める仕組みです。

```jsp
<%-- JSPのJavaコード記述形式 --%>

<%  ...Javaコード...  %>          ← スクリプトレット（処理）
<%= 式 %>                          ← 式（値を出力）
<%@ page import="..." %>          ← ディレクティブ（設定・import）
<%@ include file="..." %>         ← 別ファイルのインクルード
```

### login.jsp の解説

```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
<!DOCTYPE html>
<html lang="ja">
<head>
  <link rel="stylesheet" href="<%= request.getContextPath() %>/css/style.css">
  <%-- request.getContextPath() は アプリのベースURL（例: "/za-navi"） --%>
</head>
<body>
<div class="login-page">
  <div class="login-card">

    <%-- Logicからエラーメッセージが渡されていれば表示 --%>
    <% if (request.getAttribute("errorMsg") != null) { %>
    <div class="alert alert-danger"><%= request.getAttribute("errorMsg") %></div>
    <% } %>

    <%-- フォーム送信先は ControlServlet。action=doLogin でログイン処理を依頼 --%>
    <form action="<%= request.getContextPath() %>/ControlServlet" method="post">
      <input type="hidden" name="action" value="doLogin">
      <input type="text" name="userId" placeholder="例: user001" required>
      <input type="password" name="password" required>
      <button type="submit">ログイン</button>
    </form>
  </div>
</div>
</body>
</html>
```

`<input type="hidden" name="action" value="doLogin">` は **ControlServletへの命令** です。
どのボタンを押したかを、この隠しフィールドで伝えます。

### menu.jsp の解説


**フラッシュメッセージ**とは：

## 12. 画面フローと機能の全体像

### ログインから始まる全体フロー

```
[ ブラウザで http://localhost:8080/za-navi/ を開く ]
    ↓
[ index.jsp ] → ControlServlet?action=login にリダイレクト
    ↓
[ login.jsp ] ← LoginLogicが "/WEB-INF/jsp/login.jsp" を返す
    ↓ IDとパスワードを入力してログイン
[ ControlServlet?action=doLogin にPOST ]
    ↓
[ LoginLogic.doLogin() ] → DBで認証
    ↓ 成功 → セッションに userId/userName/isAdmin/bId を保存
    ↓
[ redirect: ?action=menu または ?action=adminMenu ]
    ↓
[ menu.jsp または adminMenu.jsp ]
```

### 座席予約フロー（一般ユーザー）

```
メニュー → 行先登録 → 「出社」を選択
    ↓
reserve.jsp (stage=base)   ← 拠点を選択（三田/芝浦/中野）
    ↓
reserve.jsp (stage=floor)  ← フロアを選択（1F/2F）
    ↓
reserve.jsp (stage=area)   ← エリアを選択（A/B/C）＋フロア画像表示
    ↓
reserve.jsp (stage=seat)   ← 座席を選択（A-01〜A-10）＋エリア画像表示
    ↓ 座席をクリック → doReserve にPOST
    ↓
ReserveLogic.doReserve()   ← DBに予約を登録
    ↓
reserveOK.jsp              ← 予約完了画面
```

## 13. よくあるJavaの書き方パターン解説

### パターン1：null チェックの書き方

```java
// NG：NullPointerException が起きる可能性
if (name.equals("田中")) { ... }

// OK：定数側で呼び出す（nameがnullでも例外にならない）
if ("田中".equals(name)) { ... }

// OK：Objects.equals を使う
if (Objects.equals(name, "田中")) { ... }
```

### パターン2：三項演算子

```java
// if文の短縮形
String result = condition ? "真の場合" : "偽の場合";

// 実例（埋有率バーのクラス名）
String barClass = rate < 50 ? "" : rate < 80 ? "med" : rate < 100 ? "high" : "full";
```

### パターン3：try-with-resources

```java
// Java 7以降：try(...) の中でリソース（Connection, PreparedStatement など）を宣言すると
// ブロックを抜けたときに自動的に close() が呼ばれる
try (Connection conn = DBUtil.getConnection();
     PreparedStatement ps = conn.prepareStatement(sql)) {
    // ここでエラーが起きても conn と ps は必ずクローズされる
}
```

### パターン4：Java Streams API

```java
// 従来の書き方（for文）
long count = 0;
for (Seat seat : allSeats) {
    if (usageMap.containsKey(seat.getSeatId())) {
        count++;
    }
}

// Streams を使った書き方（同じ意味）
long count = allSeats.stream()
    .filter(seat -> usageMap.containsKey(seat.getSeatId()))
    .count();
```

`stream()` → `filter()` → `count()` のように、処理をパイプラインのようにつなぐ書き方です。

### パターン5：Map の使い方

```java
// Map<キーの型, 値の型>
Map<Integer, String> seatUsage = new HashMap<>();
seatUsage.put(1, "1001");   // seatId=1 を userId="1001" が使用
seatUsage.put(5, "1023");   // seatId=5 を userId="1023" が使用

// 値を取得
String userId = seatUsage.get(1);  // "1001"

// キーが存在するか確認
if (seatUsage.containsKey(3)) { ... }

// LinkedHashMap は入れた順序を保持する
Map<String, Object> row = new LinkedHashMap<>();
```

### パターン6：instanceof とキャスト

```java
// JSPでセッションから取り出すとき（戻り値が Object 型）
Object rateObj = item.get("rate");

// キャスト前に型チェック（ClassCastException を防ぐ）
if (rateObj instanceof Integer) {
    int rate = (Integer) rateObj;
}

// または三項演算子で（このシステムでの実際の書き方）
long used = usedObj instanceof Long ? (Long)usedObj : ((Integer)usedObj).longValue();
```
